### S1-01 [high / design-rethink / confirmed] Без платного ключа Ahrefs весь автоматический discovery даёт 0 доменов: цепочка «с нуля» встаёт на шаге 1
`backend/app/services/discovery.py:175`
- Доказательство: discovery.py:175-177: `if ask and getattr(ahrefs,'api_key',None)=='': ... return kept, len(ask), set(memo), ['ключ AHREFS_API_KEY не задан']`; discovery.py:320: `keep = [n for n in fresh if n not in auto or n in drs]` — любой auto-домен без DR выбрасывается, а не сохраняется. Живой прогон run_discovery на реальных фидах: «Nominet (.uk): 11136 строк → наши зоны 9049 → DR≥5: 0 · registry.mx: 499 → 193 → 0 · EMD: 0 · DR недоступен — 9242 пропущено (ключ AHREFS_API_KEY не задан)», inserted=0, domains в БД = 0. POST public/domain-rating-free без ключа → 403 Forbidden. В .env ключ пуст. Тест test_empty_ahrefs_key_asks_nothing закрепляет это как норму. Majestic Million (бесплатный прокси) не годится: из 11 641 кандидата в топ-1M попал 1.
- Живая проба: E2E run_discovery: inserted 0 за 1,74 с; curl POST api.ahrefs.com/v3/public/domain-rating-free без Authorization → 403.
- Предложение: Переосмыслить вход воронки: платный DR не должен быть единственным условием появления кандидата. (1) Оператору — решение по ключу Ahrefs (без него M1 мёртв, это не баг окружения, а архитектурная зависимость). (2) Резервный бесплатный фильтр вместо «всё или ничего»: при пустом/упавшем ключе пропускать в `discovered` ограниченный топ-N кандидатов по дешёвым признакам (RDAP-возраст >= min_age для зон с RDAP, длина/цифры/дефисы, EMD-подобность) с пометкой «DR не проверен» и жёстким лимитом на прогон, а ценность решать на W4. (3) Для оценки ссылочной массы без Ahrefs проверить Common Crawl webgraph domain-ranks (бесплатно, не проверено) или Wayback CDX-счётчик снимков как грубый прокси. (4) Если ключ появится — сразу проверить в Задаче 17, что dr_free принимает ключ-уровень вашего тарифа.

- Предложение: Решение оператора: (а) включить DropCatch (ToS на скачивание публичных списков не препятствует — оператору перечитать п.24-25 и п.9), добавить DaysOut3 и дедуп по домену между днями; (б) дописать источники для .com/.net/.org: Pre-Release/Drop Auctions у DropCatch и/или собственная разница зонных файлов (Verisign TLD zone access / ICANN CZDS — доступ и сроки одобрения не проверены); (в) честно писать на /settings и в Пульте «пул .com/.net/.org: 0, пока источник выключен» — сейчас оператор видит зелёные Nominet/mx и думает, что международный пул есть. Для лейна free вердикт «занят» → reject_reason not_acquirable (aparser/whois → scoring.acquirability_verdict). creation всегда none для .mx и .co (example.co: «registered: none» хотя домен существует) — возраст из whois недоступен. ### S1-05 [high / bug / confirmed] Словарь стоп-слов истории только английский и русский: испанская/нидерландская/словенская грязь проходит как «чистая»

### S1-06 [medium / bug / confirmed] Предохранитель RDAP общий на все зоны, а SIDN (.nl) отвечает 429 на второй же запрос: три .nl подряд отключают RDAP для .com/.co.uk до конца прогона

### S1-07 [medium / bug / confirmed] Падение всех источников завершается как успешный `done` — оркестратор и Пульт не видят отказа
`backend/app/services/discovery.py:302`
- Доказательство: discovery.py:302-305: `if not cand: jobs.report(run, ..., message=" · ".join(["нет кандидатов", *fails])); return 0`. Имитация: Nominet и mx бросают ConnectTimeout → JobRun status=done, error=None, message «нет кандидатов · Nominet (.uk): упал (ConnectTimeout) · registry.mx: упал (ConnectTimeout)». Транспорт Cloudflare живой и быстрый (p50 около 250-380 мс, токен active, 20 зон, один аккаунт), модульные тесты зелёные (61 passed в 8 CF-файлах). Реальная проверка вскрыла три существенные вещи. ## 7 — M5 публикация + замкнутость цепочки + оркестрация

Жёсткие инварианты держатся: нет авто-approve, оркестратор не зовёт confirm/execute/mark_caught/mark_edited, publish берёт только edited, денежный гейт и политика переходов покрыты тестами. Но цепочка «с нуля» разорвана в нескольких местах, и два места, которые сейчас ломают M4/M5, видны вживую.

КАРТА ЦЕПОЧКИ (статус за статусом, кто делает переход, дыры):
1. discovered -> scored/rejected. Автопилот (стадии discovery, score; кап cap_score=20) или кнопки /run/*. Исполнитель есть. Живой прогон v2-воронки на боксе не делался: последний discovery 2026-08-19, последний score 2026-07-21 (failed).
2. scored -> approved. Только человек (инбокс, пакет, set-status). Авто-approve нет (_decide выдаёт только scored/rejected). Инвариант держится.
3. approved -> purchasing. Кнопка «в очередь» или автопилот-стадия queue (create_order, деньги не тратит; auto_queue по умолчанию выкл). Провайдер по умолчанию 'backorder' (RU), для .com/.net он не покупает. Дыра: канала покупки международных доменов нет (NameSilo не реализован, подпроект 2).
4. purchasing -> purchased. Человек: confirm_order(ставка) -> execute -> poll/mark_caught. Для международного домена честный путь один: кнопка «купил руками» (approved -> purchased). Дальше всё руками: регистрация, NS, продление.
5. purchased -> site(provisioning). Автопилот (стадия provision) или кнопка make-site. Сайт создаётся без оффера и без языка. Дыра: никто не привязывает оффер и рынок сайта.
6. provisioning -> content. provision(): CF-зона -> ждёт NS (awaiting_ns, исполнитель — человек у регистратора, RegistrarClient.set_nameservers = NotImplementedError) -> A-запись -> vhost -> CF ssl=full -> status=content. Дыры: origin-сертификата нет (HTTPS через CF не заработает), проверки «сайт реально отвечает» нет, аккаунт CF не выбирается (глобальный токен), aaPanel сейчас заблокирован IP-whitelist и lockout.
7. content -> page draft. Автопилот (стадия generate) или кнопка. LLM сейчас не работает (см. находку 1). Язык всегда ru при автопилоте, оффер берётся «первый активный». Графики нет.
8. draft -> edited. Только человек (/pages/{id}/save -> mark_edited). Орка не зовёт. Дыра: гейт принимает пустое тело и любой исходный статус; массовой редактуры нет, пропускная способность = ручная.
9. edited -> published. Автопилот (стадия publish) или кнопка; в сервисе гейт на статус edited. Дыры: нет проверки, что сайт уже provisioned (доказано), нет верификации результата по HTTP, страница без CSS/меню/мета/sitemap.
10. published -> indexed. check_index (SearXNG site:) ставит только index_status страницы. Сейчас у SearXNG мертвы все движки, поэтому результат всегда unknown. Статусы Domain.live, Site.monitoring/pruned нигде не выставляются, M6 lifecycle — заглушка NotImplementedError, продления доменов никто не отслеживает.

ВЕРДИКТ: «с нуля до выливки» сегодня невозможно по четырём независимым причинам: (а) LLM не отвечает, (б) aaPanel недоступен и ещё и блокируется lockout'ом, (в) нет покупки/NS для международных доменов, (г) в публикуемой странице нет ни графики, ни локализации. Что хорошо: все внешние вызовы быстрые, когда доступны (CF ~250 мс, aaPanel 48–143 мс, SearXNG ~100 мс), панель отвечает за 20–130 мс, кроме /diag (17,8 с).

## Критик полноты

Аудит сильный в M1/M3-транспорте/латентности, но цепочку «с нуля до сайта» он не замыкает. Что осталось недоказанным и непокрытым:

1. Живая часть цепочки за пределами M1 не наблюдалась ни разу. aaPanel заблокирован (бан), LLM-генерация мертва (mistral 403, mistral-small 429, ollama через LiteLLM не достаёт хост), SearXNG пуст, платежей нет. В aapanel.py:262-267 стоит комментарий UNVERIFIED про параметр auth_to у apply_cert_api. Никто не проверил, доживёт ли выпуск LE по http-01 за проксированной Cloudflare-зоной в статусе pending.
2. Несколько находок «critical/high design-rethink» — это запланированные подпроекты, а не дефекты (docs/v2/CLAUDE.md:74,116,151,156: «до подпроекта 2», NameSilo, подпроект 3 — контент и медиа). Недостающие NameSilo, графика и локализация нужно отделить от настоящих багов реализованного кода. Баги: ложный ok CF-sync, потеря rel, дыра в классификаторе истории, утечка api_key, отсутствие предохранителя aaPanel, гейт редактуры. Иначе приоритеты исказятся.
3. Измерения загрязнены параллельным запуском сегментов. Сегменты 1-8 одновременно били в одни и те же A-Parser, Wayback, SearXNG, Ollama и aaPanel.
