# Ревью плана M1 и документов v2: находки и правки

Дата: 2026-10-01. Объект: `02-m1-discovery-scoring-spec.md`, `03-m1-plan.md`, `01-master-spec.md`,
`CLAUDE.md`, `research/*.md`. Это рабочий список для правок плана, после правок файл можно удалить.

**Как проверяли.**
- Пять независимых ревьюеров по участкам плана (задачи 1–4, 5–7, 8–10, 11–13, 14–17). Каждый
  применил код плана к копии `backend/` и прогнал тесты плана и весь сьют.
- Миграция 0025 прогнана на PostgreSQL 16: upgrade → downgrade → upgrade.
- Discovery прогнан на объёмах 134 тыс. + 266 тыс. строк.
- Живьём сверены Nominet, registry.mx, бутстрап IANA и RDAP восьми серверов белого списка.
- Сухой прогон всего плана исполнителем на Sonnet в изолированном worktree — §8.

**Итог.** Тесты каждой задачи на коде плана проходят, шаги «должен упасть» честные, миграция и
объёмы в порядке. Но:
- **4 места ослабляют курацию перед деньгами (§1).** Денежный гейт `confirmed_by_human` не
  обходится, но грязный или непроверенный домен доезжает до кассы как чистый.
- **Бюджет units посчитан неверно (§2):** автопилот гоняет скоринг раз в час, а не раз в сутки.
- **У трёх новых внешних клиентов нет предохранителей (§3)** — это повтор инцидента v1 с TCI.
- **Десятки существующих тестов, которые план ломает, в плане не названы — даны правилом «почини
  упавшие» (§5, §8).** Самое опасное: чистка Задачи 16, исполненная буквально, удалит тесты денежного
  гейта.

Обозначения: **К** — критично, **В** — важно, **М** — мелочь. «план:N» — строка `03-m1-plan.md`.

## 0. Решения оператора — приняты 2026-10-01

Ответ оператора: «Р1 пофиг, Р2 автоматически не одобряем ничего, Р3–Р5 ок, оллама ок, можем ещё
мистраль API дать — тоже ок». Р7 без ответа — берётся рекомендация. Ниже — точный дизайн, по нему
правится план.

**Р1 → рекомендация.** `link_signals.spam_anchor_ratio(anchors, domain, market_lang=None)`: нелатинский
скрипт НЕ считается спамом, если совпадает с языком прошлого сайта. Карта: `ja` → кана + CJK,
`zh` → CJK, `ko` → хангыль, `th` → тайский, `ru/uk/bg/sr/kk/be/mk` → кириллица. `_deep_one` передаёт
`s.sig.get("market_lang")`. Тесты: японский анкор на .com при `market_lang="ja"` → 0.0, при `"es"` → 1.0.
Задача 13.

**Р2 → авто-одобрения нет вообще. `approved` ставит только человек** (кнопка или пакет).
- `_decide(score, sig, manual_review_at)` → `"scored" if score >= manual_review_at else "rejected"`.
  Гарды `wayback_checked` / `whois:` / ошибки риска / `age_years is None` из `_decide` уходят — их
  роль переходит к `bulk_ok` (пакетное одобрение), где они и так в основном живут через `blind_reason`.
- **`bulk_ok` обязан исключать всё, что раньше держали гарды `_decide`**, плюс новое:
  - история не `clean` (уже есть);
  - `blind_reason`: ошибки `wayback:`/`whois:`/`webrisk:`/`blacklist:`/`ahrefs:` (уже есть или
    добавляют Задачи 10–11);
  - возраст неизвестен (`whois_created` и возраст из архива пусты) — новая строка `blind_reason`;
  - `deep_checked is not True` — «анкоры НЕ проверены» (Задача 13, уже в плане);
  - `topical_relevance < 0.3` — «прошлая тема далека от VPN» (инвариант 4; `None` не исключает —
    «тема не определена» не ослепляет, спека §3.1);
  - `score is None` (EMD) — уже держит SQL `score >= x`, плюс тест.
- `approve_at` остаётся в БД и в `/settings` под новым смыслом: **«порог сильного кандидата»** —
  превью-счётчик и значение по умолчанию для поля «пакет от скора» в инбоксе (сейчас там зашито 0.8).
  В `_decide` не участвует.
- Тесты, где скоринг ждал `approved`, ждут `scored`. Гард-тесты v1 («never auto-approves …») не
  удаляются, а переписываются в «не попадает в `_bulk_candidates`» — это их новый смысл.
- Владелец: Задача 8 (`_decide`, `compute_score`, перевод тестов), Задача 13 (`bulk_ok`: deep, тема,
  возраст; e2e «чистый → `scored` и в пакете»), Задача 14 (подпись `approve_at`), Задача 15
  (дефолт пакета = `approve_at`).
- Находки 1.3 (пустые анкоры) и 1.11 (гард-тест возраста) остаются в силе — теперь для `bulk_ok`.

## 1. Гейты и инварианты

**1.1 К. `legacy_ru` и `tld_closed` открывают ручной путь к кассе** (план:3485, 3942–3946; `transitions.py:53`).
- В `DIRTY_REASONS` их нет. Поэтому в `/domains/pool` у таких строк есть «↩ вернуть в approved»,
  `transitions.check` пропускает перевод, а оркестратор ставит домен в очередь (`_stage_queue`).
- `ARCHIVE_SQL` (план:1412) перезаписывает `rkn` на `legacy_ru` у «отмытых» v1-доменов
  (`approved` с `reject_reason='rkn'` есть на боксе).
- **Правка:** в Задаче 5 (там же, где появляется `legacy_ru`) добавить `"legacy_ru"` и
  `"tld_closed"` в `DIRTY_REASONS`, тест «легаси-домен нельзя вернуть в approved».

**1.2 К. Чистка Задачи 16 удалит тесты денежного гейта** (план:3939–3946).
- Grep по `rkn` велит удалять всё, чего нет в списке допустимых остатков. В нём нет:
  - `transitions.dirty_reason` (ветка `rkn_listed`);
  - флага РКН в `pool.html`;
  - `test_transitions.py` (стр. 48–268, `rkn` там — пример грязи);
  - `test_migration_0025.py`, литерала v1 в `test_fresh_install.py`, `integrations/registrar.py`.
- **Правка:** дописать их в допустимые остатки; явной строкой: «тесты гейтов (`test_transitions`,
  `test_acquisition*`, `test_bulk*`) не удалять, легаси-коды в них — фикстуры».

**1.3 К. Пустой ответ анкоров = «проверено»** (план:3420).
- `deep_checked=True` ставится безусловно. Пустой `anchors` → `ratio=None` → нейтральные 0,5 → гард
  пропускает. Симуляция: DR 35, RD 900, анкоров 0 → скор 0,858 → **approved**.
- **Правка:** `s.sig["deep_checked"] = ratio is not None or not s.sig.get("referring_domains")`;
  при RD > 0 и пустых анкорах — `errors.append("deep:empty")`. Тест «RD 900 + anchors=[] → не approved».

**1.4 К. Перескор отмывает спам-домен** (план:3485; `transitions.py:99–106`).
- `dirty_reason` смотрит только `reject_reason`. Отказ `spam_anchors` → «перепроверить» → W4 или W6
  падает → `scored`, `reject_reason=None` → кнопка «одобрить» → очередь выкупа. Для РКН и блэклиста
  такая страховка есть (`test_rescore_early_exit_does_not_erase_rkn_evidence`).
- **Правка:** `_deep_one` пишет `sig["spam_anchors"] = ratio is not None and ratio > max`;
  `_commit_result` сохраняет его через `_kept`; `dirty_reason` проверяет
  `score_breakdown.spam_anchors is True`. Тест по образцу прецедента.

**1.5 В. Угроза Web Risk не снимается и не держит** (план:2672–2676).
- Web Risk пишет общую колонку `blacklisted=True`. Без DQS чистый повторный ответ её не сбрасывает,
  а машина может поставить `approved` домену с `dirty_reason=="blacklist"`.
- **Правка:** Web Risk `blacklisted` не трогает; `dirty_reason` проверяет
  `score_breakdown.webrisk_threats` (он уже сохраняется через `_kept`).

**1.6 В. Фильтр `?lang=` + пакетное одобрение одобряет невидимое** (план:3805–3847).
- На `/domains?lang=pl` оператор видит 3 польских домена, а «✓ Одобрить пакет» берёт все `scored`
  со скором выше порога на всех языках.
- **Правка:** при `f_lang` прятать форму пакета (проще всего) либо прокинуть `lang` в
  `bulk-preview`/`bulk-approve` и `_bulk_candidates`. Пустое состояние: «по языку X ничего нет».

**1.7 В. Пинг DropCatch в `/diag` каждые 5 минут при непрочитанном ToS** (план:3925; спека §6).
- `main._diag_loop` обновляет диагностику каждые 300 с → 288 вызовов `GetFileUrl` в сутки при
  выключенном источнике. Нарушает инвариант 6; сбой выключенного источника красит глобальный баннер.
- **Правка:** `need_cred` для dropcatch = `"1"`, только если `sources_enabled["dropcatch"]`; иначе
  skip. В Задаче 17 ждать «skip» до проверки ToS. Поправить спеку §6.

**1.8 В. Сбой Ahrefs в W4 навсегда хоронит домены как `low_score`** (план:2866–2870).
- Без RD скор падает ниже 0,4 → `rejected`. `score_pending` берёт только `discovered` — сам домен
  больше не перепроверится. С протухшим ключом (401) так уходит весь прогон.
- **Правка:** исключение пачки → вся пачка `unresolved_why="ahrefs_failed"`, следующие пачки не
  отправлять. Тест «ошибка пачки → домены остаются `discovered`».

**1.9 В. Сеть в тестах: настоящий RDAP и ключи из `.env`** (план:2525, 2680, 3520).

  `_make_clients()` — с Задач 10–11. В контейнере бокса с боевыми ключами тесты упрутся в рубильник.
- **Правка:** одна autouse-фикстура в Задаче 3: обнуляет `AHREFS_API_KEY`, `WEBRISK_API_KEY`,
