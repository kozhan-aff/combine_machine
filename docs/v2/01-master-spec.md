# Комбайн v2 — мастер-спека: международный VPN-портфель

Дата: 2026-10-01. Статус: **согласовано оператором** (2026-10-01). Спека подпроекта 1 — ревизия 3, план — `03-m1-plan.md`, ревью плана — `04-plan-review.md`.
Источники фактов — `research/*.md`, у каждого факта там есть пометка о проверке.

## 1. Что меняется и зачем

Комбайн v1 работал только с .ru/.рф: backorder.ru, cctld.ru, reg.ru, sweb, optimizator, РКН.
**v2 полностью уходит из РФ.** Основная причина — реклама VPN в РФ запрещена с 01.03.2024, с 01.09.2025
действуют штрафы (см. `research/cctld-markets.md`). Новые домены — международные: .com и gTLD
плюс ccTLD целевых рынков.

**Критерий успеха всего v2** — полный цикл на реальном домене:
1. домен найден и оценён машиной;
2. куплен по API после подтверждения человеком;
3. NS переведены на один из CF-аккаунтов;
4. поднят на aaPanel с Origin-сертификатом, каждый шаг проверен;
5. контент на языке рынка отредактирован человеком;
6. опубликован и попал в индекс.

## 2. Решения оператора (2026-10-01)

| Вопрос | Решение |
|---|---|
| Вертикаль | **Только VPN**. Казино, адалт, фарма в истории домена — отказ, как и раньше |
| Рынки | Почти все, кроме **США и Китая**. Упор на **LatAm и небольшие страны Европы**, плюс англоязычные и часть Азии. Языки — местные |
| Масштаб | **30–100 сайтов за 6 месяцев**, бюджет **$50–500 за домен** |
| Оплата | **Крипта** (пополнение баланса регистратора) |
| Регистратор | На старте достаточно одного с полным API: **NameSilo** (BTC, только баланс, drop-catch .com/.net). Потом Dynadot под ccTLD. Namecheap — если есть свой аккаунт |
| Редактура | **Оператор сам**, по подстрочному русскому переводу в панели |
| Хостинг | **Один VPS** с aaPanel + **~10 аккаунтов Cloudflare**, сайт назначается на аккаунт |
| Код | Эволюция в этом репо (решение делегировано, обоснование — §5) |
| Порядок | **Сначала поиск и скоринг доменов** (выбор оператора), затем покупка + провижн, затем контент, затем MCP |
| Одобрение доменов | **Автоматического одобрения нет** (2026-10-01): `approved` ставит только человек — кнопкой или пакетом |
| LLM для темы прошлого сайта | Ollama на боксе; Mistral API тоже допустим |
| Разработка | В отдельном чате на модели Sonnet 5.5, по документам из `docs/v2/` |

## 3. Инварианты: не обходить

Перенесены из v1 и действуют во всех подпроектах.

1. **Денежный гейт.** Заказ уходит регистратору ТОЛЬКО при `confirmed_by_human=true`. Никаких покупок
   на автопилоте, включая drop-catch и ставки. Цена фиксируется в заказе на гейте; исполнение её
   не пересчитывает. При неизвестном исходе (таймаут, 5xx) — `maybe_sent`, отмена блокируется,
   повтор безопасен (класс `AmbiguousSend` из v1).
2. **Гейт редактуры.** Страница публикуется ТОЛЬКО из статуса `edited`. `draft → edited` делает человек.
   LLM-критик — только подсказка.
3. **Чистая история.** Адалт, фарма, казино, гемблинг, спам в истории — жёсткий отказ (детерминированный
   классификатор видимого текста Wayback, не LLM).
4. **Тематическая преемственность** (новое, из политики Google «expired domain abuse»). Тема прошлого
   сайта показывается человеку и входит в скор. Жёстко не отклоняет, но домен с далёкой прошлой темой
   не должен проходить незаметно.
5. **Независимость сайтов.** Никакой перелинковки сайтов портфеля. Один Origin-сертификат на домен
   (multi-SAN раскрыл бы портфель).
6. **Легальность источников.** Ничего не автоматизируем вопреки ToS: ExpiredDomains.net, SpamZilla,
   VirusTotal public, бесплатный Safe Browsing, WIPO GBD — только руками или никак. Неподтверждённый
   ToS (DropCatch) — источник выключен по умолчанию, пока оператор не проверит.
7. **Не гадать форматы.** Формат ответа внешнего сервиса снимается живым запросом и кладётся в
   фикстуры тестов ДО написания парсера (урок v1: cctld терял дату из-за парсинга «по докстрингу»).
8. **Герметичные тесты.** Рубильник сети `_no_live_network` в `conftest.py` не трогать. Ловушки —
   наследники `BaseException`. Платные ключи в тестах обнуляются autouse-фикстурой: результат не
   зависит от `.env`.
9. **Нет авто-одобрения** (решение оператора 2026-10-01). Скоринг ставит максимум `scored`;
   `approved` — только действие человека. Пакетное одобрение — тоже действие человека, но берёт
   лишь полностью проверенные домены (история, возраст, риск, анкоры; тема: далёкая от VPN — вне
   пакета, не определена — не исключает; см. спеку M1 §3.2).

## 4. Полный цикл (v2)

```
[1 discovery] → [2 скоринг] → инбокс → человек: approve
   → [3 выкуп: заказ → ГЕЙТ (человек) → регистратор API]
   → [4 провижн: CF-аккаунт → зона → NS → A → Origin CA → aaPanel → SetSSL → strict → verify]
   → [5 контент: бриф → данные → черновик на языке → перевод RU → критик → ГЕЙТ редактуры]
   → [6 публикация: статический HTML → выкладка → IndexNow → индексация]
```

Статусы домена прежние: `discovered → scored|approved|rejected → purchasing → purchased → live → dropped`.
Лейны прежние: `free` (регистрируется сейчас) и `bid` (ловится в момент дропа, «занят» до дедлайна — норма).

## 5. Архитектура: что остаётся, что уходит

**Почему эволюция, а не новый репо.** Из ~10,6 тыс. строк `backend/app` к РФ привязано около
1 тыс. строк интеграций и два сервиса (discovery, acquisition). Остальное — проверенное ядро с 777
тестами, его переписывание не дало бы ничего, кроме новых багов.

**Остаётся (ядро):**
- `services/jobs.py` — реестр задач в PostgreSQL, single-flight, отмена;
- волновой конвейер `_run_waves` в `services/scoring.py`;
- оба гейта (`acquisition.py`, `transitions.py`);
- панель (`api/panel.py`, `templates/`, дизайн-система `docs/DESIGN.md`);
- клиент Cloudflare и мультиаккаунтная модель CF (`models/cloudflare.py`, `cf_secret.py`, `cf_sync.py`);
- клиент aaPanel (переделка SSL и транспорта — в подпроекте 2);
- классификатор Wayback (`wayback._visible_text`);
- контент, критик, публикация;
- A-Parser — для whois:43 по зонам без RDAP и для конкурентов.

**Уходит:**
- источники backorder-фид, cctld, reg.ru, sweb (подпроект 1);
- РКН, whois_tci, Ahrefs через A-Parser с капчей, Safe Browsing через A-Parser (нарушает ToS),
  `indexed_echo` через SearXNG (подпроект 1);
- выкуп через backorder.ru и optimizator (подпроект 2).

**Новое:** источники DropCatch, Nominet, registry.mx, ручной список и генератор EMD; клиенты Ahrefs API v3,
RDAP, Web Risk, NameSilo; Origin CA; SSH-транспорт к aaPanel; назначение сайта на CF-аккаунт;
многоязычный контент с подстрочником; MCP-адаптер.

## 8. Риски

- **Бесплатный DR от Ahrefs могут отозвать** (лицензия запрещает систематический сбор). Снижение
  риска: DR один раз на домен (таблица `dr_seen`, 4 суток), офлайн-префильтр по зонам. Фолбэки:
  бесплатный DR не принимает пачку (проверка — Задача 17, шаг 3а) → поштучный бесплатный DR с капом для
  Nominet и .mx (лимит 60 запросов в минуту), DropCatch выключен; бесплатный DR отозвали → DR через
  `batch-analysis` (25 units/домен) с капом.
- **Автопилот гоняет свип раз в час**, капы units стоят на прогон. Защита месяца — пол остатка
  `units_floor` (300 тыс.): ниже него платные волны не запускаются.
- **ToS DropCatch не прочитан** — источник выключен до проверки.
- **Web Risk требует биллинг GCP.** Без него волна W3 пустая, домены помечаются «риск не проверен»
  и в пакетное одобрение не идут.
- **Пороги не откалиброваны.** DR, RD, бюджеты units — стартовые значения; калибровать по
  водопаду воронки на первом живом прогоне.
- **Пропускная способность редактуры** — реальный потолок масштаба (подпроект 3).
- **VPN в Турции, ОАЭ, Вьетнаме, Индонезии:** там надёжнее .com на языке страны, чем ccTLD.

## 9. Процесс разработки

- На подпроект: спека → план → subagent-driven-development (implementer + `combine-reviewer` на задачу)
  → whole-branch ревью → мерж.
- TDD. Тесты офлайн. Живые форматы — в фикстуры (инвариант 7).
- После каждого подпроекта — живой прогон на боксе 192.168.1.77 и обновление раздела «Текущее состояние»
  в `docs/v2/CLAUDE.md`.
- Заявление субагента «проверено визуально» само по себе не доказательство — перепроверять (урок v1).
