# Тексты и дизайн от конкурентов: дизайн

**Дата:** 2026-10-10. **Статус:** согласовано с оператором в диалоге (подход «конвейер с явными
артефактами», досье + тексты + критик + дизайн-макет + автопилот), ждёт ревью текста спеки.
**Повод:** первый живой сайт `tunnelnotes.xyz` поднят целиком, но результат оператор отверг:
«дизайн и тексты не годятся». Причины разобраны: генерация идёт по одному универсальному промпту
без фактов (бренд вымышленный), от конкурента берутся только H2/H3 одной случайной страницы,
дизайн вычисляется из хеша домена и не знает содержания.

## 1. Цель

Сайт на купленном домене собирается так, как это сделал бы редактор с дизайнером:
1. изучить, что пишут и как выглядят топ-страницы по теме в этом гео и языке;
2. написать своё, лучше и полнее, по правилам оператора, с проверяемыми фактами;
3. сверстать под этот сайт отдельный дизайн, а не шаблон;
4. вычитать и опубликовать без клика оператора; оператор правит уже живой сайт.

Критерий: `tunnelnotes.xyz` пересобран этим конвейером под реальный оффер **Durev VPN**,
страницы опубликованы автоматически, оператор видит на карточке сайта досье, макет, вердикты
критика и может перерисовать или переписать с комментарием.

## 2. Решения, принятые оператором (не обсуждаются в реализации)

- **Подход 1 из трёх**: исследование и сборка брифов — код; модель зовётся как чистая функция
  (писатель, критик, дизайнер); артефакты хранятся в БД и видны в панели. Отвергнуты «агент на
  сайт» (невоспроизводимо, шлюз headless) и «свободный HTML на каждую страницу» (разнобой стиля).
- **Дизайн от конкурентов — «оба»**: токены из HTML/CSS всегда, скриншоты через Browserless по
  тумблеру.
- **Гейт редактуры переезжает на машину.** Правило 1 CLAUDE.md («публикуется только `edited`»)
  остаётся в коде без изменений: `publish_site` берёт только `edited`, `draft` не публикуется.
  Меняется, КТО ставит `edited`: при включённом тумблере `auto_edit` это делает критик после
  прохождения чек-листа. Это осознанно отменяет пункт «Не автоматизируем draft→edited» спеки
  `2026-07-18-editorial-critic-design.md`: тогда критик был советчиком человеку, теперь человек
  правит уже опубликованное. При выключенном `auto_edit` поведение прежнее.
- **Денежный гейт не затронут** ничем в этой спеке.
- **Первый реальный оффер — Durev VPN** (RU/СНГ-аудитория, VLESS/Shadowsocks, сайт и Telegram-бот).
  Факты в датасет снимаются с официальных источников живьём; чего не нашли — пишем «неизвестно»,
  не выдумываем.
- **Правила письма оператора** — папка `content_guides/` в репо (создана), заливка файлами в папку
  И через панель.

## 3. Архитектура: пять единиц

```
provision ─► research ─► design ─► generate ─► critic ─► publish
             (досье)    (макет)   (писатель)  (edited)   (как есть)
```

| Единица | Файл | Делает | Зависит от |
|---|---|---|---|
| Досье | `services/research.py` + `integrations/browserless.py` | SERP → страницы конкурентов → текст/структура/факты/CSS-токены/скриншоты → `site_research` | A-Parser, SearXNG, Browserless, nh3 |
| Правила | `services/guides.py` | читает `content_guides/`, склеивает по языку и типу страницы, лимит | ФС |
| Писатель + критик | `services/content.py`, `services/content_critic.py` | бриф → `PageDoc` (JSON) → HTML-блоки; критик → `edited` или замечания → переписать | шлюз LLM, досье, правила, `vertical_data` |
| Дизайнер | `services/designer.py` | дизайн-бриф → макет (layout.html + theme.css + theme.json) → проверка кодом → скриншоты → `site_theme` | шлюз LLM, досье, Browserless, `site_builder` |
| Сборка | `services/site_builder.py` | рендер `PageDoc` в макет сайта; старый генератор по хешу — запасной | `site_theme` |

Интеграции — только транспорт (`integrations/`), логика в `services/` (конвенция проекта).

## 4. Досье конкурентов — `services/research.py`

### 4.1 Запросы
По одному на тип страницы, на языке рынка сайта (`Domain.market_lang`, иначе язык оффера), плюс
один общий:
- review: `t(lang, "q_review", brand)` → «{brand} обзор» / «{brand} review»;
- comparison: «{brand} vs» / «{brand} против»; howto: «как настроить {brand}» / «{brand} setup»;
- общий: «лучший VPN {страна}» / «best VPN {country}» — даёт структуру рынка, не бренда.
Словарь запросов — в `services/locales.py` рядом с `title_*` (язык без словаря → `ValueError`,
как сейчас у генерации).

### 4.2 Выдача
`AParserClient.serp_urls(query, limit=10)` (SE::Google, работает вживую 2026-10-10); при пустом
ответе/ошибке — `SearxngClient.search(query, language)`; оба пустые → досье по этому запросу
пустое, причина в `site_research.note`. A-Parser отдаёт `google.com/goto?url=…`-редиректы — это
живой факт, `fetch_html` их проходит; в досье пишем конечный URL из ответа Net::HTTP, если он есть,
иначе исходный.

Фильтр `_NOISE` из `competitor.py` расширяется: + домен самого бренда, + магазины приложений,
+ дубли по домену (один URL на домен). Берём первые **5** живых (скачались, ≥ 300 слов видимого
текста).

### 4.3 Извлечение (stdlib + nh3, без новых зависимостей)
- `text` — видимый текст, та же функция, что у Wayback (`wayback._visible_text`: судим по тексту,
  не по сырому HTML);
- `headings` — дерево h1–h3 в порядке документа (парсер из `competitor.py`, переезжает сюда);
- `tables` — таблицы как списки строк (текст ячеек), не более 5 на страницу;
- `faq` — пары «вопрос?/ответ» из `<details>`, `h3`+абзац с `?`, JSON-LD FAQPage;
- `numbers` — числа с контекстом ±8 слов (цены, серверы, страны, дни возврата): источник фактов
  для брифа и для критика;
- `css_tokens` — из `<link rel=stylesheet>` (скачиваем до 3 файлов, ≤ 300 КБ каждый) и
  инлайн-стилей: `font-family` (топ-3 по частоте), цвета (топ-6 по частоте без белого/чёрного),
  `max-width` контейнера (медиана), наличие компонентов по эвристике (таблица сравнения,
  блок плюсов/минусов, рейтинг-звёзды, аккордеон FAQ, sticky CTA);
- `screenshot_path` — при `RESEARCH_SCREENSHOTS=true`: Browserless `POST /screenshot`
  (viewport 1366×768, `fullPage: true`, PNG). Файлы: `<RESEARCH_DIR>/<site_id>/<rank>.png`, где
  `RESEARCH_DIR` — смонтированный `/workspace/combine/research` шлюза (бокс `D:\claude-code\workspace`),
  чтобы дизайнер в Claude Code мог их открыть по пути. Для этого в `docker-compose.yml` backend и worker
  получают bind той же хост-папки (`D:\claude-code\workspace\combine` → `/workspace/combine`). Формат
  ответа Browserless снимается живьём до кода (дисциплина Треда D), фикстура кладётся в тесты.

### 4.4 Хранение — таблица `site_research` (миграция `0036`)
```
id, site_id FK, kind (review|comparison|howto|market), query, rank, url, final_url, domain,
fetched_at, words, headings JSON, tables JSON, faq JSON, numbers JSON, css_tokens JSON,
text TEXT, screenshot_path, note
```
Свежесть: повторный `research` не тянет, пока строки моложе 30 дней; кнопка «пересобрать досье»
на карточке сайта удаляет строки сайта и тянет заново. Текст хранится целиком (нужен критику для
проверки на копирование), но не выводится в панель целиком — только счётчики и заголовки.

### 4.5 Отказы
Ни одного живого источника ни по одному запросу → `research` возвращает `{"status": "empty",
"reason": …}`, сайт остаётся в `content`, генерация **не стартует** (сегодня она шла с пустым
брифом молча). Причина — словами на карточке и в `job_run.message`.

## 5. Правила письма — `services/guides.py` + папка `content_guides/`

- Чтение: все `*.md|*.txt` из корня + `content_guides/<lang>/` + `content_guides/<kind>/`,
  по алфавиту, склейка с разделителями `--- <путь> ---`. Итог > 40 000 символов → обрезка по
  файлам с конца и предупреждение в `job_run.message` и на карточке.
- Панель: карточка «Правила письма» на `/settings`: список файлов с размером и датой, форма
  загрузки (multipart, только `.md`/`.txt`, ≤ 200 КБ, имя файла — только `[A-Za-z0-9._-]`, выбор
  подпапки из фиксированного списка: корень/язык/тип), кнопка удалить. Файлы пишутся в
  `content_guides/` репо (на боксе `D:\combine_machine\content_guides\`), `git pull` их не трёт
  (папка в git, оператор коммитит сам или оставляет локально — обе ситуации работают).
- Безопасность: путь строится только из белого списка подпапок + санированного имени;
  никакого `..`, абсолютных путей, симлинков.

## 6. Писатель и критик — `services/content.py`, `services/content_critic.py`

### 6.1 Бриф (код, не модель)
Из досье по типу страницы: темы, которые есть у ≥ 3 из 5 конкурентов (по нормализованным
заголовкам), факты `numbers` с URL-источником, таблицы (структура колонок), FAQ-вопросы,
«пробелы» — темы общего рыночного запроса, которых нет у конкурентов по бренду. Плюс
`vertical_block(brand)` из `vertical_data`, оффер (бренд, промокод, гео, язык), правила письма.

### 6.2 Схема ответа писателя — `PageDoc` (Pydantic v2)
```
meta: {title, description}
verdict: {score 1–10, summary (≤ 2 предложения), for_whom, not_for_whom}   # review
pros: [str]  cons: [str]                                                      # review, comparison
sections: [{h2, paragraphs: [str], bullets: [str] | None, h3s: [{h3, paragraphs}] | None}]
table: {columns: [str], rows: [[str]]} | None                                 # comparison
steps: [{title, text, platform}] | None                                       # howto
faq: [{q, a}]
sources: [url]   # какие URL досье реально использованы
```
Модель просят вернуть **только JSON**; парсинг через `model_validate_json`; невалидно → один
повтор с текстом ошибки валидации в промпте; снова невалидно → страница `draft` с замечанием,
дальше не идём. Объём (по сумме слов): review 1500–2200, comparison 1200–1800, howto 900–1400;
выход за границы — замечание критика, не отказ парсера.

Хранение: `Page.blocks` JSON (новая колонка, миграция `0036`), `Page.body` — отрендеренный HTML
блоков (как сегодня, чтобы редактор страницы, `_sanitize`, `render_html` и publish работали без
переделки). Ручная правка `body` в редакторе панели остаётся: после неё `blocks` помечается
устаревшим (`blocks_stale=true`), повторный рендер из блоков не затирает ручную правку.

### 6.3 Промпты
- Системный: роль редактора + правила письма (§5) + требования схемы + «не выдумывать числа,
  которых нет в фактах; каждую цифру сопровождать источником в `sources`».
- Пользовательский: бриф (§6.1). Модель — `LLM_WRITER_MODEL` (по умолчанию `sonnet` через шлюз
  `:3033`), запасная — текущая цепочка шлюза.

### 6.4 Критик — расширение `content_critic.py`
Сохраняем `critic_score/critic_notes/critic_checked_at` (спека 07-18). Добавляем:
- **проверки кодом (до модели):** шинглы по 12 слов против `site_research.text` всех источников
  сайта — совпадение ≥ 1 шингла = копирование, список фраз в замечания; disclosure и бренд
  присутствуют (как в `render_html`); язык страницы = язык сайта (эвристика по алфавиту/стоп-словам);
  объём в границах; каждая цифра из текста встречается в `numbers` досье или в `vertical_data`
  (числа без источника — замечание «факт без источника: …»);
- **проверка моделью:** чек-лист из правил письма (§5) + «текст полезнее и конкретнее
  конкурентов по темам брифа?» — ответ JSON `{pass: bool, issues: [str], score}`;
- **вердикт:** `pass` = ни одного замечания кодом И `pass` от модели. При `auto_edit=true`
  и `pass` → `mark_edited` вызывается **сервисом критика** (тот же путь, что у кнопки; никакого
  второго пути в `edited`). Не `pass` → писатель получает замечания и переписывает (максимум
  **2** круга), после — `draft` с замечаниями на карточке и в `job_run.message`.
- Модель — `LLM_CRITIC_MODEL` (по умолчанию `opus`, при недоступности `sonnet`).

## 7. Дизайнер — `services/designer.py`

### 7.1 Дизайн-бриф (код)
Тема/ниша, бренд, язык, гео, тип аудитории; токены конкурентов (§4.3) как «что принято на этом
рынке, не копировать, а учесть»; список скриншотов с путями (если есть); перечень обязательных
слотов и компонентов (§7.2); ограничения: без внешних URL, шрифты системные или из короткого
белого списка самохостинга (файлы кладёт сборщик как ассеты сайта), без JS; запрет дефолтов
из навыка (кремовый фон + терракота, тёмный + кислотный акцент, карточный SaaS-кит, ALL-CAPS
ярлыки). Текст навыка `frontend-design` (плагин Claude Code) вшивается в системный промпт
**копией в репо** `backend/app/prompts/frontend_design.md` — не зависимость от контейнера шлюза;
обновляется руками.

### 7.2 Контракт макета — «theme bundle»
```
theme.json: {name, palette: {bg, surface, fg, muted, accent, accent_fg, border}, fonts: {body, head},
             principles: [str], memorable: str, container_px}
layout.html: полный документ со слотами {{lang}} {{title}} {{description}} {{canonical}} {{head_extra}}
             {{brand}} {{nav}} {{hero}} {{disclosure}} {{content}} {{offer}} {{footer}} {{build_id}}
theme.css:   стили каркаса + классы компонентов: .verdict .pros-cons .cmp-table .steps .faq .section
             .offer .disclosure .nav (имена фиксированы контрактом; при рендере сборщик
             переименовывает их в хеш-классы сайта, как сегодня `Theme.k()`, — footprint)
```
Скриншоты конкурентов модель видит только при `RESEARCH_SCREENSHOTS=true` (пути в брифе; шлюз
запускает Claude Code в `/workspace`). **Риск:** `server.js` передаёт `--allowedTools` только для
MCP-серверов, встроенный `Read` в headless-режиме может быть запрещён — проверяется живьём первым
шагом плана. Если запрещён: либо оператор добавляет `Read` в `--allowedTools` шлюза (одна строка
в `server.js`), либо скриншоты остаются только для глаз оператора на карточке, а дизайнер получает
токены и словесное описание. Код конвейера не зависит от исхода: пути в брифе — опциональны.

### 7.3 Проверка кодом (не на веру)
Все слоты присутствуют ровно по разу; все классы контракта объявлены в CSS; нет `<script>`,
`@import`, `url(http…)`, `<link href=http…>`; CSS парсится простым токенизатором (скобки
сбалансированы); размер ≤ 120 КБ. Провал → один повтор с перечнем ошибок; снова провал →
макет не сохраняется, сайт использует запасной генератор по хешу, причина на карточке.

### 7.4 Визуальная проверка
Сборщик рендерит тестовую страницу (блоки-образцы всех типов) в макет, Browserless снимает
1366 и 390 px; код проверяет `document.scrollWidth <= innerWidth` (без горизонтального
скролла) через `POST /function` Browserless (формат снимается живьём). Скриншоты → карточка
сайта. Кнопка «перерисовать» с полем комментария: комментарий добавляется в бриф, новая версия.

### 7.5 Хранение — таблица `site_theme` (миграция `0036`)
```
id, site_id FK, version, status (ok|failed), theme JSON, layout_html TEXT, css TEXT,
brief TEXT, model, screenshots JSON, operator_note, created_at
```
`Site.template` (пустое поле) начинает хранить `theme_id` активной версии; `NULL` = запасной
генератор по хешу. Один вызов дизайнера на сайт; повторный — только кнопкой или при отсутствии
`ok`-версии.

### 7.6 Сборка — `site_builder.render_document`
Новый путь: если у сайта есть `ok`-макет — слоты заполняются из `PageDoc`-блоков (рендер блоков
в HTML с классами контракта → хеш-классы), иначе старый путь без изменений. Навигация, disclosure,
оффер, canonical, build-id вставляет **код**, как сегодня. Инварианты независимости сайтов
сохраняются: хеш-классы, хеш-имена ассетов, никаких общих URL.

- `AS_OF` обновляется.

## 10. Тесты (офлайн, герметично)

Живые образцы снимаются один раз, кладутся в `backend/tests/fixtures/`: SERP A-Parser (с
`goto`-редиректами), HTML двух конкурентов + один CSS, ответ Browserless `/screenshot` и
`/function`, ответы писателя (валидный, невалидный), критика, дизайнера (валидный, с ошибками
контракта). Тесты:
- досье: фильтры, извлечение (текст/заголовки/таблицы/FAQ/числа/токены), свежесть 30 дней, пустое
  досье → генерация не стартует;
- правила: порядок, лимит, белый список путей загрузки, отказ на `..`/плохое имя/размер;
- писатель: бриф из досье (темы ≥ 3/5, факты с источниками), валидация `PageDoc`, один повтор;
- критик: шинглы ловят копию, цифра без источника — замечание, `pass` → `edited` ТОЛЬКО при
  `auto_edit=true` и ТОЛЬКО через `mark_edited`; два круга и стоп; `publish_site` из `draft` —
  по-прежнему отказ (регрессия гейта);
- дизайнер: проверка контракта (слоты, классы, запреты), провал → запасной генератор; рендер
  блоков в макет; хеш-классы; старый путь без макета не изменился (существующие тесты
  `site_builder` проходят без правок — условие безопасности, как у волновой архитектуры);
- оркестратор: порядок стадий, тумблеры, капы, `job_run` сообщения.

## 11. Что НЕ входит

- Рисунки/фото (ImageProvider остаётся svg-local), растеризация og-картинки.
- Больше трёх типов страниц, блог, перелинковка между сайтами портфеля (запрещена инвариантом).
- Переводы одной страницы на несколько языков; один сайт = один язык.
- Изменение денежного гейта.
- Замена редактора панели на WYSIWYG (волна 3).
